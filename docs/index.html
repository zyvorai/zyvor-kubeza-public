Why

Edge clusters should be boring.

You run clusters in shops, plants and racks nobody visits. Kubeza decides the pieces an edge site needs, ships them together, and gives you one tool to check, install, upgrade and back them up.

Small

Built on K3s

A pinned, checksum-verified upstream K3s underneath. Kubeza does not fork or patch it.

Complete

Gateway and network included

Setura, a Gateway API controller, replaces the default ingress. zkube-net is the built-in CNI. No assembly.

Calm

Dry run first

zkube plan shows every file before install. Commands that change something have --dry-run.

Features

Everything one binary can carry.

One stdlib-only binary

zkube is a single Go binary with no third-party dependencies. Install, join nodes, upgrade, back up and audit from one command line.

Setura Gateway built in

The Gateway API CRDs and the Setura controller come with the distribution instead of Traefik. Migration helpers convert existing Ingresses.

zkube-net, the built-in CNI

Our own CNI with nftables NetworkPolicy enforcement and a node self-test. Choose it with --cni zkube.

Offline-first

Build a bundle with checksums on a connected machine, carry it to an air-gapped site, install with --offline.

Pinned add-ons

cert-manager, KubeVirt and CDI are pinned to real upstream releases and verified by sha256 at enable time.

Doctor and smoke

zkube doctor --smoke checks nodes, CRDs, the GatewayClass and the controller, then sends a real request. Every check comes with a fix.

--json everywhere

Every command with output can emit JSON, so scripts and fleet tooling never parse prose.

Upgrades, backups, hardening

Upgrade with a snapshot, health gate and rollback. Backups are verified. Hardening audits can export evidence.

No phone-home

Nothing is sent to us. Support bundles redact secrets and are never uploaded.

zkube-net

A network you can ask questions.

When traffic is blocked, zkube why net explains the verdict for one source, destination and port, and names the rule that decided it.

$ zkube why net SRC DST PORT
  Allow or deny, and the rule that decided it.
$ zkube net ruleset
  The compiled nftables ruleset, as the node runs it.
$ zkube net selftest
  A kernel self-test in throwaway namespaces.

Quickstart

Five commands.

$ zkube preflight            # can this machine run it? read only
$ zkube plan server          # exactly what install would do
$ sudo zkube install server # K3s, Setura, Gateway API CRDs
$ sudo zkube doctor --smoke # including a real request
$ sudo zkube backup now      # verified

Air-gapped? Build with zkube bundle, carry the tarball over, install with --offline. The v0.1.0-rc1 pre-release has the binary; the commands above are what testers run.

The never-brick promise

The licence never stops a running cluster.

The licence is a signed offline key checked locally, with no call home. If it expires or is missing, your running cluster keeps running.

FAQ

Questions, answered plainly.

Is it K3s?

No. Zyvor Kubeza is built on K3s and adds its own tooling and components. K3s is a trademark of SUSE; Kubeza is not affiliated with SUSE or Rancher.

Can I download it?

A pre-release for testing, v0.1.0-rc1, is on the releases page (Linux amd64 and arm64). It is not for production.

Why Setura instead of Traefik?

Setura is a Gateway API controller from Zyvor, built into the distribution, so ingress uses the standard Gateway API from day one.

What if my licence expires?

Your running cluster keeps running. Only new installs and upgrades are affected.

Does it need the internet?

No. Bundles can be built elsewhere and installed offline. Nothing is sent back to Zyvor.

Is the source available?

The source repository is private. Early-access users can ask for access.
